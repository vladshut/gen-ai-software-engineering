Banking Transaction
Pipeline

A multi-agent system that ingests raw transactions and runs them through validation → fraud scoring → settlement, producing an auditable final record for every transaction.

Created by  Vladyslav Shut
Overview

What the system does

  • Loads raw transactions from sample-transactions.json.
  • Validates structure, amount (Decimal > 0, ≤ 2 dp), and ISO-4217 currency.
  • Scores fraud with a fixed additive model → a decision band.
  • Settles approved/review (FX → USD + 0.1% fee), holds flagged, leaves rejected.
  • Writes a final record per transaction and asserts a known outcome oracle.

Agent 1

Transaction Validator

  • Enforces the required-field, amount, and currency contract.
  • Amount must parse as Decimal > 0 with ≤ 2 decimal places.
  • Currency must be in the accepted ISO-4217 set.
  • Rejections carry a rejection_reason.

Rejects, e.g.

  • TXN006 — currency XYZ
  • TXN007 — negative amount
  • missing fields, > 2 dp

Agent 3

Settlement Processor

  • approved / review → settled: FX-convert to USD, apply 0.1% fee.
  • flagged_review → held (not settled).
  • rejected → stays rejected.
  • Records fx_rate, amount_usd, fee_usd, net_usd.

Money handling

  • All amounts are decimal.Decimal — never floats.
  • Fees use ROUND_HALF_UP, min $0.01.
  • Static, documented FX rates to a USD base.
Implementation

Contracts that keep it auditable

Message envelope

Every hop serializes a JSON Message: message_id, timestamp, source_agent, target_agent, data.

PII masking

Account numbers never logged in plaintext — masked to last 4 (****1001) everywhere.

Frozen contracts

Currencies, fraud weights, FX rates, and the oracle live in common/constants.py — one source of truth.

Every run asserts this oracle — all 8 decisions match, or the pipeline fails loudly.

Design decision

Why deterministic agents — no LLMs

The rules are fixed and known. An LLM would be slower, costlier, and unauditable — for zero gain.

  • Correctness — exact, reproducible; makes the oracle meaningful.
  • Auditability — every decision is traceable on paper.
  • Cost & latency — a rule check is free and instant.
  • Scale — high volume is an infrastructure problem, not an intelligence one.

Scaling · bonus

High-volume --fast mode

Same deterministic agents, stream JSONL instead of per-transaction files. The win is dropping I/O, not adding intelligence.

ModeThroughputvs file-based
File-based, sequential (graded path)~2,300/s1×

--fast --workers 7~140,000/s~50–60×

Output is byte-identical regardless of worker count — pure functions over independent transactions.
